# SPEC.md — ALGORITHM: Review of Economic Research — Journal Platform Specification

Version 1.0 · September 2026 · Engineering source of truth (see `CLAUDE.md` for working rules)

---

## 1. Purpose and success criteria

Build the official website and full editorial system of the open-access electronic economics
journal **ALGORITHM: Review of Economic Research** (Uzbek: «АЛГОРИТМ» — иқтисодий тадқиқотлар шарҳи;
Uzbek Latin: «ALGORITM» — iqtisodiy tadqiqotlar sharhi; Russian: «АЛГОРИТМ» — обзор экономических
исследований). Short code **ARER**.

The site must, on day one, satisfy every technical requirement of:
- the **Uzbekistan Higher Attestation Commission (OAK)** for recognised e-journals, and
- the **Scopus CSAB** website/online-availability criteria, plus **DOAJ** and **Google Scholar**
  inclusion criteria,
and must look and behave like a top-tier international journal site (reference quality bar:
MDPI *Economies*, Springer *Journal of Economic Growth*, AEA *AER*, OUP *QJE*), while remaining
calm, academic and fast.

Success = all checks in §15 pass on a clean machine via `docker compose up`, and the code is
pushed to `https://github.com/diyorbek20037773/algorithm_journal`.

## 3. Personas and roles

| Role (Django Group) | Who | Capabilities |
|---|---|---|
| `reader` (anonymous) | Everyone | Read/download everything, search, cite, RSS, no registration needed |
| `author` | Any registered user | Submit, track status, respond to reviews, upload revisions, view own published articles page |
| `reviewer` | Registered, flagged by editor | See anonymised manuscripts assigned to them, submit structured review, recommend |
| `section_editor` | Staff | Manage submissions in own sections: screening, assign reviewers, recommend decision |
| `editor_in_chief` | Staff | Everything section editors can + final decisions on all submissions, assign section editors, manage board, publish issues |
| `production_editor` | Staff | Copyediting/typesetting stage, galleys, metadata completion, DOI assignment, issue scheduling |
| `admin` (superuser) | Tech admin | Django admin, SiteSettings, users, integrations, audit log |

A user may hold several roles. Role checks via permission mixins in `apps/accounts/permissions.py`.

- `ReviewAssignment`: `round` FK, `reviewer` FK, `invited_by`, `invited_at`, `responded_at`,

  (`invited`, `accepted`, `declined`, `submitted`, `cancelled`, `overdue`).
- `Review`: `assignment` OneToOne, `recommendation` (`accept`, `minor_revision`, `major_revision`,

  text), `comments_to_editor` (confidential), `attachment` (annotated PDF, must be stripped of
  author metadata — set `is_anonymised` flag with PDF metadata scrub via `pikepdf`), `submitted_at`,
  `quality_rating` (set by editor 1–5 afterwards).
- `EditorialDecision`: `submission` FK, `round` FK, `decided_by`, `decision` (`desk_reject`,
  `send_to_review`, `accept`, `minor_revision`, `major_revision`, `reject`, `resubmit`),
  `letter` (rendered from template, editable), `decided_at`, `emailed_at`.
- `RevisionRequest`: `submission` FK, `round` FK, `due_at` (minor: 30 days, major: 60 days),
  `submitted_at`, `response_letter`.
- `Discussion` + `DiscussionMessage`: threaded messages per submission between roles
  (author↔editor, editor↔reviewer, editor↔production), with `visibility` set; used for queries.
- `EditorNote`: private notes.
- `ProductionTask`: `submission` FK, `stage` (`copyediting`, `author_proof`, `typesetting`,
  `metadata`, `doi`, `scheduled`), `assignee`, `status`, `due_at`, `notes`.

#### Workflow FSM (`apps/submissions/workflow.py`, use `django-fsm-2` or hand-written transitions with permission + side effects)

```
draft ──submit──▶ submitted ──editor assigned──▶ screening
screening ──desk_reject──▶ rejected
screening ──(plagiarism ok & scope ok) send_to_review──▶ under_review
under_review ──all reviews in──▶ awaiting_decision
awaiting_decision ──minor/major──▶ revision_requested ──author uploads──▶ resubmitted ──▶ under_review (new round) | awaiting_decision
awaiting_decision ──accept──▶ accepted ──▶ copyediting ──▶ author_proof ──▶ typesetting ──▶ ready_to_publish
ready_to_publish ──publish online first──▶ published_online_first ──assign to issue & publish issue──▶ published
awaiting_decision ──reject──▶ rejected
any pre-accept state ──author withdraw──▶ withdrawn
```
Every transition: permission check, timestamp, `AuditLog` entry, email notification(s) via Celery,
`Discussion` system message. Reviewer never sees `SubmissionAuthor`, `title_page`, cover letter, or
other reviewers' identities; author never sees reviewer identities; templates for reviewer views
must use a dedicated anonymised serializer/context — write tests proving no leakage (string
assertions on rendered HTML for author names/emails).

### 5.5 metrics

- `AccessEvent`: `article` FK, `kind` (`view`, `download`), `galley` FK nullable, `occurred_at`,
  `ip_hash` (salted SHA-256, never raw IP), `country` (via `geoip2` if DB present, else null),
  `user_agent_hash`, `is_bot` (COUNTER robots list regex + heuristics), `session_key_hash`.
  Double-click filter: same ip_hash+article+kind within 30 s counts once.
- `DailyArticleStat`: `article`, `date`, `views`, `downloads` (aggregated nightly, raw events
  pruned after 90 days). Denormalise totals on `Article`.
- `EditorialKPI` snapshot per month: submissions received, desk-rejected, sent to review, accepted,
  rejected, acceptance rate, median days to first decision, median review duration, active
  reviewers, author countries distribution — used in dashboard and public `/statistics/`.

### 5.6 plagiarism

```python
class PlagiarismProvider(Protocol):
    slug: str

    def submit(
        self, submission: Submission, file: SubmissionFile
    ) -> str: ...  # returns external id
    def fetch_result(self, external_id: str) -> PlagiarismResult | None: ...


class ManualProvider: ...  # editor uploads report + %; default


class IThenticateProvider: ...  # config: ITHENTICATE_URL, ITHENTICATE_API_KEY; raises NotConfigured
```
`PLAGIARISM_PROVIDER` env selects. Submission cannot move `screening → under_review` unless a
result exists and `similarity_percent <= SiteSettings.similarity_threshold` (override allowed by
EIC with a logged justification).

## 6. Public pages — content and behaviour

### 6.1 Home (`/`)
Sections, top to bottom (all fully server-rendered):
1. Optional announcement bar (from SiteSettings).
2. **Masthead / hero**: journal name (4-language aware), one-line descriptor, and a credibility strip:
   `e-ISSN`, `DOI prefix`, `Open Access · CC BY 4.0`, `No APC`, `Double-blind peer review`,
   `Monthly`, plus live KPIs from `EditorialKPI` (median days to first decision, acceptance rate) —
   rendered only when ≥ 10 decisions exist, otherwise hidden. Primary CTA "Submit your manuscript",
   secondary "Author guidelines".
3. **Current issue**: cover (or generated typographic cover), Vol/No/Year, 6 articles with
   authors, section tag, DOI, PDF button; "View full issue".
4. **Online First**: latest 4 (hidden if none).
5. **Browse by section / JEL**: 8 section cards with counts; JEL top-level chips.
6. **Most read (30 days)** and **Latest announcements** side by side.
7. **Indexing & identifiers**: active IndexingService logos only, ORCID/Crossref badges.
8. **Author journey strip**: 4 steps (Read scope → Prepare (template/checklist) → Submit → Review
   in ~8 weeks) linking to pages.
9. Footer: publisher, address, contact email, e-ISSN, certificate, license, links (privacy, ethics,
   sitemap, OAI-PMH, RSS), language links.

### 6.2 Article landing page — the most important page
Order and elements (Highwire tags + JSON-LD in `<head>`):
- Breadcrumb: Home › Archive › Vol X No Y (Year) › Article.
- Section label, article type, "Open Access · CC BY 4.0" badge, "Online First" badge if applicable.
- Title in current language; `<h1>`; translated titles collapsible ("Title in other languages").
- Authors: name, superscript affiliation markers, ORCID icon-link (green iD, official SVG), ✉ for
  corresponding (mailto only when `is_corresponding`), affiliations list with country.
- Metadata block (definition list): DOI (as `https://doi.org/...`), Published, Received / Revised /
  Accepted, Volume/Issue/Pages, JEL codes (linked), Keywords (linked chips).
- Abstract in current language; tabs/accordion for the other languages (EN always present).
- Action rail (sticky on desktop): Download PDF (size), View HTML (if XML galley), **Cite** (opens
  HTMX modal with style dropdown: APA, MLA, Chicago, Harvard, Vancouver, GOST; copy button; export
  BibTeX / RIS / EndNote / CSL-JSON), Share (copy link, X, LinkedIn, Telegram, email), Metrics
  (views, downloads, Crossref cited-by count if available — fetched nightly via Crossref REST,
  cached).
- Statements: Funding, Conflict of interest, Data availability, Acknowledgements, AI-use disclosure
  (when provided).
- **References**: numbered list, each with DOI link and "Google Scholar" search link; `<ol>` with
  `itemprop="citation"`.
- "How to cite" box with APA string pre-rendered (no JS needed — Google Scholar friendly).
- Related articles: by shared keywords/JEL (max 4).
- Author panels: for each author, link to author page.
- License notice with CC badge SVG and text.
- Retraction/withdrawal banner when applicable (with notice text, kept online per COPE).

`<head>` must include: `citation_title`, `citation_author` (one per author, "Family, Given"),
`citation_author_institution`, `citation_author_orcid`, `citation_publication_date` (YYYY/MM/DD),
`citation_online_date`, `citation_journal_title`, `citation_journal_abbrev`="ARER",
`citation_issn`, `citation_volume`, `citation_issue`, `citation_firstpage`, `citation_lastpage`,
`citation_doi`, `citation_pdf_url` (absolute, language-neutral route), `citation_abstract`,
`citation_keywords`, `citation_language`, `citation_publisher`, `citation_fulltext_world_readable`;
Dublin Core `DC.*` equivalents; `rel=canonical`; `hreflang` × 4 + `x-default`; OG/Twitter; JSON-LD
`ScholarlyArticle` with `isPartOf` → `PublicationIssue` → `PublicationVolume` → `Periodical`
(`issn`), `author` as `Person` with `@id` = ORCID URL and `affiliation`, `license`, `identifier`

### 6.3 Issue TOC

## 7. Submission wizard (`/submit/`)

   AI-use disclosure textarea (may be "None").
2. **Files**: anonymised manuscript (PDF/DOCX ≤ 20 MB, required), title page (required, contains
   authors), figures/tables, data/supplementary (optional). Server-side MIME check; DOCX word count

5. **Review & submit**: summary; final confirm; on submit: status `submitted`, ID `ARER-2026-0001`,

## 10. Multilingual implementation details

- `LANGUAGES = [("en","English"),("uz","Oʻzbekcha"),("uz-cyrl","Ўзбекча"),("ru","Русский")]`,
  `LANGUAGE_CODE="en"`, `LocaleMiddleware`, `i18n_patterns(prefix_default_language=True)`.
- Add a custom locale for `uz-cyrl` (Django lacks it): `LANG_INFO` extension in
  `config/locale_info.py` with `name_local="Ўзбекча"`, `bidi=False`, and `locale/uz_Cyrl/`.
  Register date/number formats (`formats.py`) for both Uzbek variants and Russian.
- `MODELTRANSLATION_LANGUAGES = ("en","uz","uz-cyrl","ru")` (hyphenated, identical to `LANGUAGES`;
  modeltranslation derives the field suffix `_uz_cyrl` itself), `MODELTRANSLATION_FALLBACK_LANGUAGES
  = {"default": ("en",), "uz-cyrl": ("uz","en"), "uz": ("uz-cyrl","en"), "ru": ("en",)}`.
- Django ships no `uz-cyrl` locale, so `/uz-cyrl/` URLs only work once `locale/uz_Cyrl/LC_MESSAGES/django.mo`
  exists: run `compilemessages` in the Dockerfile build step **and** in `make dev`/`make test`; commit
  `.po` files only (`.mo` git-ignored).
- `apps/core/translit.py`: deterministic Uzbek Latin ↔ Cyrillic transliterator (handle digraphs
  `sh, ch, ng, oʻ/o', gʻ/g', yo, yu, ya, ts, ye` at word start, apostrophe forms ʼ ’ ' `, capitalisation,
  and a small exception dictionary). Unit-tested with ≥ 40 cases. A `pre_save` hook fills empty
  `*_uz_cyrl` fields from `*_uz` and marks `auto_translit=True` in a JSON field so editors can see
  what was machine-generated.
- Static translations: you author `django.po` for uz, uz_Cyrl, ru completely (no untranslated
  msgids at the end — CI runs a `polib`-based script `scripts/check_translations.py` asserting
  `len(po.untranslated_entries()) == 0` and `len(po.fuzzy_entries()) == 0` for every `.po`). Use consistent academic
  terminology: e.g. EN "Peer review" → UZ "Taqriz (ekspertiza)" / RU "Рецензирование"; "Submit" →
  "Maqola yuborish" / "Отправить статью"; "Issue" → "Son" / "Выпуск"; "Volume" → "Jild" / "Том".
- Language switcher: `<a hreflang>` links to the same path in each language (use
  `translate_url`), plus `<link rel=alternate>`; cookie `django_language` set on switch.
- Fonts must cover Cyrillic + Latin Extended (Uzbek `oʻ`, `gʻ`): see DESIGN_BRIEF.

## 11. Security requirements (implement + test)

- Django `SECURE_HSTS_SECONDS=31536000`, `SECURE_SSL_REDIRECT`, secure/HttpOnly/SameSite cookies,
  `CSP` via `django-csp` (self + fonts.googleapis/gstatic + matomo host; nonce for inline scripts),
  `X-Frame-Options=DENY`, `Referrer-Policy=strict-origin-when-cross-origin`.
- Passwords: min 12 chars, `CommonPasswordValidator`, `UserAttributeSimilarityValidator`, Argon2 hasher.
- 2FA: `django-otp` TOTP; middleware forces enrolment for staff roles on next login; recovery codes;
  admin site wrapped with OTP-required admin.
- Rate limits: login 5/min/IP, signup 3/hour/IP, contact 3/hour/IP, submission create 10/day/user,
  search 60/min/IP. `django-axes` lockout after 10 failures for 30 min.
- Uploads: allowed extensions per file kind (`pdf docx doc odt tex zip xlsx csv png jpg svg`),
  MIME sniff, size caps, ClamAV optional (`CLAMAV_HOST`; if unset skip and log), files stored
  outside web root, served via authenticated views for unpublished content; published galleys public.
- PDF anonymisation: strip metadata (Author/Creator/Producer) from reviewer attachments and, on
  request, from author manuscripts (`pikepdf`).
- Audit: log login/logout/failed login, role changes, decisions, publish/unpublish, settings
  changes, file deletions; viewer in admin dashboard with filters; retention 2 years.
- Dependency pinning via `uv.lock`; `pip-audit` step in CI (non-blocking warning).
- Secrets only via env; `SECRET_KEY` generated in `.env` by `make init`.

- Lighthouse-class targets: mobile ≥ 80, desktop ≥ 90, accessibility ≥ 95, best practices ≥ 95,
